# The Strata container (LXC)

The scripts are in `../../proxmox/strata-lxc/`; the exhaustive runbook is its
`README.md`. This page is the summary and the decisions, written so it can be
reproduced with different IDs, storage names and hardware.

## Create

Copy the scripts to the host and run the audit first:

```sh
scp -r proxmox/strata-lxc root@<HOST_IP>:/root/
ssh root@<HOST_IP>
bash /root/strata-lxc/00-check-host.sh
```

Every value has a default; override the ones that differ:

```sh
CTID=<CTID> \
CT_HOSTNAME=<CT_HOSTNAME> \
STORAGE=<STORAGE> \
ROOTFS_GB=<ROOTFS_GB> \
MEMORY_MB=<MEMORY_MB> \
SWAP_MB=<SWAP_MB> \
CORES=<CORES> \
BRIDGE=<BRIDGE> \
bash /root/strata-lxc/10-create-strata-lxc.sh
```

| Variable | Reference | Notes |
|---|---|---|
| `CTID` | `121` | must be free |
| `CT_HOSTNAME` | `strata-2` | any name |
| `STORAGE` | `nvme` | the fast directory storage |
| `TEMPLATE_STORAGE` | `local` | where the Debian template is cached |
| `ROOTFS_GB` | `380` | model + working copy + headroom |
| `MEMORY_MB` | `57344` | 56 GiB |
| `SWAP_MB` | `4096` | 4 GiB |
| `CORES` | `28` | all threads, so the engine picks its workers |
| `BRIDGE` | `vmbr0` | |
| `RUN_SCRIPT` | `run-iq3_s.sh` | written into the unit; setup generates this name |
| `AUTO_SETUP` | `1` | `0` to run `setup.sh` yourself |

The audit and verify scripts take `GPU_PCI` (reference `05:00.0`) and
`NVME_PATH` (`/mnt/nvme`); the create script does not need them.

The create script:

- downloads the Debian 13 template if it is not cached;
- creates the container unprivileged with `fuse=1,nesting=1`, the requested
  RAM/swap/cores and a raw rootfs on `<STORAGE>`, DHCP, `onboot: 1`;
- adds `lxc.prlimit.memlock: unlimited`;
- starts once to read the **container-side** render GID (Debian 13: **992**),
  stops;
- maps `dev0 /dev/kfd,gid=<render>` and
  `dev1 /dev/dri/renderD128,gid=<render>`;
- installs the build/runtime packages;
- clones Strata to `/opt/Strata`;
- writes `strata.service` (`LimitMEMLOCK=infinity`, `STRATA_AUX_CPUS=auto`);
- starts `setup.sh --backend hip` in a tmux session.

Do **not** pass `cardN`. It renumbers across boots and a stale entry stops the
container from starting. ROCm compute needs only `/dev/kfd` and `renderD128`.

The render GID is resolved *inside* the container, not on the host. If your
distro uses a different GID, the script reads it; do not copy the host's.

## Setup choices

The interactive `setup.sh` asks for the model, size, context, KV and options.
The reference answers:

```
Model:      Qwen3.8-Flash-Next (GSQ-RCO, ISTA-DASLab)   -> 1
Size:       IQ3_S (84 GB download, ~50 GB RAM)          -> 4
Context:    256K (262144); 200K and 128K also work      -> 6
KV:         8-bit (q8)                                  -> 1
Images:     on, encoder on CPU (auto)
Low-RAM:    GPU holds ~25% of experts, ~38 GB in RAM (auto)
Projection: off                                         -> n
```

These choices are model-specific. For another model, use the same principle:
the most compressed quantization that still fits RAM, the smallest context that
holds your conversations, and 8-bit KV when VRAM is tight.

When setup finishes it starts its own engine. **Stop it (Ctrl+C) before enabling
the service**, or two engines share the container's RAM.

```sh
systemctl enable --now strata
```

The engine sees the container's CPU topology and picks one worker per physical
core, minus one. Do not clamp or raise the worker count: measurements upstream
show that oversubscribing is a significant slowdown. `STRATA_AUX_CPUS=auto`
lets helper threads use the SMT siblings.

## The service and LAN binding

`/etc/systemd/system/strata.service` (essential parts):

```
[Service]
Environment=STRATA_AUX_CPUS=auto
LimitMEMLOCK=infinity
ExecStart=/bin/bash -lc 'exec /opt/Strata/run-iq3_s.sh'
Restart=on-failure
RestartSec=10
TimeoutStopSec=180
```

`/opt/Strata/run-iq3_s.sh` must contain:

```
--host 0.0.0.0 --port <PORT>
```

`run-*.sh` is generated by `setup.sh`; if you re-run setup, re-add `--host`.
The `<PORT>` is `8080` in the reference.

Binding `0.0.0.0` also makes the server answer to the host's own names. Add the
container address to `STRATA_ALLOWED_HOSTS` if the server rejects requests by
Host header:

```
Environment=STRATA_ALLOWED_HOSTS=<CT_IP>,<CT_HOSTNAME>
```

## Context sizing

The context is the `--max-context` value in the generated JSON (the reference
file is `/opt/Strata/strata-iq3_s.json`, in both `args` and `args_written`).

Do not jump to the maximum. Raise it one step at a time and watch VRAM and real
RAM; stop when VRAM is ~95% used or the host has under ~2 GiB free. Reference
measurements with the 20 GB card and IQ3_S:

| Context | VRAM | Real RAM | 8K prompt | 32K prompt | Host free | Notes |
|---|---:|---:|---:|---:|---:|---|
| 128K | 19.9/20.4 GiB | 41.9–42.3 GiB | 602 tok/s (16K 607) | — | ~4.5 GiB | safest; largest expert cache |
| 200K | 19.8/20.4 | 42.9–43.0 | 572 | 595 | ~4.3 | good balance |
| **256K** | **19.8/20.4** | **43.6** | **552** | **572** | **3.0** | reference; max |

The same shape applies to other cards: each context step moves VRAM from the
expert cache into the KV cache, so prefill slows and RAM rises slightly.

Keep a backup of every working profile:

```sh
pct exec <CTID> -- cp -a /opt/Strata/strata-iq3_s.json /opt/Strata/strata-iq3_s.json.<tag>
```

Revert by copying a backup back and restarting `strata`.

The client's context limit must match the server's. If the client sends more
than `max_context`, the server rejects the request.

## Why not a VM

The VM + VFIO attempt is in `../../proxmox/strata-vm/`; it hit the **Navi 31
reset bug** (the card disappears after a stop/start and needs a cold power
cycle) and **pinned the guest's RAM in the host**. The LXC keeps the host
driver: no passthrough, no reset, the host keeps its memory, and the container
sees the real CPU topology. The isolation trade is acceptable for a
single-purpose server.

## Dependencies inside the container

| Thing | Provided by |
|---|---|
| `/dev/kfd`, `/dev/dri/renderD128` | the host `amdgpu` driver, via `dev0`/`dev1` |
| ROCm runtime | the engine's `.venv` (a bundled ROCm build for the GPU arch) |
| Model / tokenizer / MTP / vision | the data directory, downloaded by `setup.sh` |
| Python | the distro + the `.venv` created by `setup.sh` |
| Service | `strata.service` (enabled) |

There is **no `amdgpu-dkms`** in the container or on the host. The host kernel
provides `amdgpu` and `kfd`; the container provides userspace only.

## Updating

```sh
pct exec <CTID> -- systemctl stop strata
pct exec <CTID> -- git -C /opt/Strata pull
pct exec <CTID> -- bash -lc 'cd /opt/Strata && ./setup.sh --backend hip'
pct exec <CTID> -- systemctl start strata
```

Re-check the run script for `--host 0.0.0.0` and the JSON for
`--max-context` after an update; setup can rewrite both. Keep the old JSON as a
backup so you can restore the context without re-downloading anything.
